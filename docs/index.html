Why now

Voice models moved onto the player's GPU.

In 2025 and 2026 shipped games started running language models inside the player's own machine, and generative AI became an ordinary line in a Steam release. The model is no longer the hard part. Getting its voice into a game's mix, at a cost an indie game can carry, is.

The problem

Pay for a full voice cast, or ship NPCs that stay silent.

Voiced dialogue is priced per line recorded or per line generated. Neither fits a game whose whole point is that players can say anything.

Recording does not scale

$1,134.95 buys one 4-hour SAG-AFTRA session for up to three voices (2025–26 rate), before studio, direction and retakes. Starfield was announced at over 250,000 lines; Skyrim shipped around 60,000. Every script rewrite is a new session.

Cloud voice turns success into a bill

Speech synthesis is about 90% of a cloud voice turn. Every player who talks costs the studio money, so a hit becomes a growing invoice. A game designer who reviewed an early build put it plainly: "sold a game for $10, player burned $15 of tokens."

A voice outside the mix sounds pasted on

Dialogue that arrives as a separate stream skips the buses, attenuation, occlusion, reverb and ducking the sound designer built. Players hear the difference before they can name it.

Who feels it most: sandbox and simulation games, with the most NPC conversations per player and the thinnest margin per copy. They are the strongest fit in our developer interviews so far.

Interruptible

The player can cut in mid-sentence. The NPC stops at once and remembers only what the player actually heard, never the words that were cut.

Stays in character

Locked to the game's lore, with no tools outside the game engine to reach for. Told to "drop the act", it answers in its own voice.

Remembers the player

Each character keeps its own memory of each player, so a returning player is recognized without being told.

Sounds like the game

The voice is an FMOD event. The sound designer's buses, 3D, reverb and ducking apply exactly as they do for recorded dialogue.

Scales with what the player hears

Only the NPC you are talking to runs the full pipeline. A market square of 240 NPCs holds at most 7 live voices; the rest bark or murmur.

No bill per player

Speech recognition, the model and the voice run on the player's GPU: $0 per turn, no API key, nothing to meter.

Proof

What exists today, and what does not.

A working prototype. Every line below is measured, shipped or labeled for what it is.

  • Verified

    Runs inside Unity 6 with FMOD for Unity 2.03.14: a real microphone, a spoken question, an in-character spoken answer through the FMOD mix.

  • Verified

    Fully local on one RTX 4080: Whisper, qwen3:8b, Kokoro. The server refuses to start if any stage falls back to the CPU.

  • Shipped

    A Windows player build that starts its own voice server: no terminal, no Python for the player.

  • Measured

    ~0.5 s from the end of the player's speech to the NPC's first audio (p50, n=10, editor idle); 0.85–1.1 s while the same GPU renders the game. Closing that gap is the next engineering target.

  • Tested

    229 automated tests on the runtime and 21 on the Unity core, including interruption races over a real socket.

  • In progress

    Structured interviews with Unity developers. Sandbox and simulation games look like the strongest fit so far.

  • Not yet

    No customers or revenue: pre-release. English speech only. Unreal + Wwise not exercised in an Editor. Phones not benchmarked.

Business model

The voice costs nothing per player. So charge per game.

Priced from measured usage against vendor rate cards: one NPC turn is 282 fresh and 700 cached prompt tokens, 23 output tokens, 92 characters of speech and 3 s of player audio.

652 conversation turns per player an all-cloud stack can fund from a $10 game at a 90% margin target.
6,587 turns when only the voice moves onto the player's GPU. Fully local, the count is unlimited: the studio's cost stops growing with its success.

Per-title license hypothesis

Game-audio middleware is licensed per title, and ReadSpeaker sells on-device game speech as a one-time license per project. VoiceRT has no per-player cost to pass on, so it can be priced the same way. No price is set yet: the developer interviews decide it.

A ceiling for studios that want the cloud

A studio that swaps in a cloud model gets a spending ceiling enforced at runtime, like the latency budget. Out of budget means an authored fallback line, never an error dialog.

Why it compounds · hypothesis, testing now

It gets cheaper per player as a game succeeds.

Success does not become a bill

With cloud voice, more players means a bigger invoice. With VoiceRT the millionth player costs what the first did, which makes talking NPCs viable in games priced like indie games.

The second character is a data file

Characters live in a world file, not in code. Once one NPC works, every next one is writing, not engineering, so use grows inside each game after the first integration.
